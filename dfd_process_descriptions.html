คำอธิบายแผนภาพกระแสข้อมูลระดับที่ 1

กระบวนการที่ 1.0 การจัดการแจ้งซ่อม

กระบวนการที่ 1.0 การจัดการแจ้งซ่อม เป็นกระบวนการหลักของระบบที่เกี่ยวข้องกับการรับแจ้ง บันทึก มอบหมาย และติดตามคำร้องแจ้งซ่อมตั้งแต่เริ่มต้นจนเสร็จสิ้น โดยมี External Entity ที่เกี่ยวข้อง ได้แก่ ผู้ใช้งาน หัวหน้างาน ผู้ดูแลระบบ และช่างซ่อม มี Data Store ที่ใช้ ได้แก่ D1 ข้อมูลคำร้องแจ้งซ่อม, D2 ข้อมูลอาคาร, D3 ข้อมูลผลการซ่อม และ D4 ข้อมูลผู้ใช้ ประกอบด้วยกระบวนการย่อย 6 กระบวนการ ดังนี้

กระบวนการที่ 1.1 บันทึกคำร้องแจ้งซ่อม

Process number 1.1
Process name บันทึกคำร้องแจ้งซ่อม
Input data ข้อมูลคำร้องแจ้งซ่อม (จาก ผู้ใช้งาน)
Output data แจ้งเตือนคำร้องใหม่ (ไปยัง หัวหน้างาน)
Data Store D1 ข้อมูลคำร้องแจ้งซ่อม
Process Description เป็นกระบวนการรับข้อมูลคำร้องแจ้งซ่อมจากผู้ใช้งาน โดยบันทึกรายละเอียดปัญหา สถานที่ และรูปภาพประกอบลงในฐานข้อมูล D1 จากนั้นส่งการแจ้งเตือนไปยังหัวหน้างานเพื่อดำเนินการตรวจสอบและมอบหมายงานต่อไป

กระบวนการที่ 1.1 ทำหน้าที่เป็นจุดเริ่มต้นของระบบแจ้งซ่อม เมื่อผู้ใช้งานพบปัญหาจะส่งข้อมูลคำร้องเข้ามา ระบบจะทำการบันทึกรายละเอียดทั้งหมดลงใน D1 ข้อมูลคำร้องแจ้งซ่อม พร้อมทั้งส่งการแจ้งเตือนไปยังหัวหน้างานโดยอัตโนมัติ เพื่อให้สามารถดำเนินการมอบหมายงานซ่อมได้อย่างรวดเร็ว

กระบวนการที่ 1.2 มอบหมายงานซ่อม

Process number 1.2
Process name มอบหมายงานซ่อม
Input data ข้อมูลการมอบหมาย (จาก หัวหน้างาน)
Output data อัปเดตสถานะ (ไปยัง D1 ข้อมูลคำร้องแจ้งซ่อม)
Data Store D1 ข้อมูลคำร้องแจ้งซ่อม, D4 ข้อมูลผู้ใช้
Process Description เป็นกระบวนการที่หัวหน้างานเลือกคำร้องแจ้งซ่อมและมอบหมายช่างซ่อมที่เหมาะสม โดยอ่านข้อมูลช่างซ่อมจาก D4 เพื่อตรวจสอบความพร้อม จากนั้นอัปเดตสถานะคำร้องใน D1 เป็น "มอบหมายแล้ว"

กระบวนการที่ 1.2 เป็นขั้นตอนที่หัวหน้างานรับผิดชอบในการพิจารณาคำร้องแจ้งซ่อมและเลือกช่างซ่อมที่เหมาะสม โดยระบบจะอ่านข้อมูลช่างซ่อมจาก D4 ข้อมูลผู้ใช้ เพื่อแสดงรายชื่อช่างซ่อมที่พร้อมรับงาน เมื่อหัวหน้างานเลือกช่างซ่อมแล้ว ระบบจะทำการอัปเดตสถานะคำร้องใน D1 เป็น "มอบหมายแล้ว" พร้อมบันทึกข้อมูลช่างซ่อมที่ได้รับมอบหมาย

กระบวนการที่ 1.3 ดำเนินการซ่อม

Process number 1.3
Process name ดำเนินการซ่อม
Input data ข้อมูลผลการซ่อม (จาก ช่างซ่อม)
Output data อัปเดตสถานะงาน (ไปยัง D1), บันทึกผลการซ่อม (ไปยัง D3)
Data Store D1 ข้อมูลคำร้องแจ้งซ่อม, D3 ข้อมูลผลการซ่อม
Process Description เป็นกระบวนการที่ช่างซ่อมรายงานผลการดำเนินงาน โดยอ่านข้อมูลคำร้องจาก D1 รับข้อมูลผลการซ่อมจากช่างซ่อม จากนั้นอัปเดตสถานะงานใน D1 และบันทึกรายละเอียดผลการซ่อมลงใน D3

กระบวนการที่ 1.3 เป็นขั้นตอนที่ช่างซ่อมดำเนินการซ่อมแซมตามที่ได้รับมอบหมาย เมื่อทำงานเสร็จสิ้นจะรายงานผลการซ่อมเข้ามาในระบบ ระบบจะทำการอัปเดตสถานะงานใน D1 ข้อมูลคำร้องแจ้งซ่อมให้เป็น "ซ่อมแล้ว" และบันทึกรายละเอียดผลการซ่อมลงใน D3 ข้อมูลผลการซ่อม เพื่อเก็บประวัติการดำเนินงาน

กระบวนการที่ 1.4 แสดงข้อมูลแจ้งซ่อม

Process number 1.4
Process name แสดงข้อมูลแจ้งซ่อม
Input data ร้องขอดูรายการ (จาก ผู้ดูแลระบบ)
Output data ข้อมูลรายการแจ้งซ่อม (ไปยัง ผู้ดูแลระบบ)
Data Store D1 ข้อมูลคำร้องแจ้งซ่อม
Process Description เป็นกระบวนการที่ผู้ดูแลระบบร้องขอดูรายการคำร้องแจ้งซ่อมทั้งหมด โดยอ่านข้อมูลจาก D1 และแสดงผลในรูปแบบรายการพร้อมรายละเอียดสถานะที่ครบถ้วน

กระบวนการที่ 1.4 เป็นขั้นตอนที่ผู้ดูแลระบบสามารถเรียกดูรายการคำร้องแจ้งซ่อมทั้งหมดในระบบ โดยอ่านข้อมูลจาก D1 ข้อมูลคำร้องแจ้งซ่อม และแสดงผลเป็นรายการที่มีรายละเอียดครบถ้วน เช่น สถานะ วันที่แจ้ง ช่างซ่อมที่รับผิดชอบ เพื่อใช้ในการติดตามและบริหารจัดการงานซ่อมแซม

กระบวนการที่ 1.5 แก้ไข/ลบคำร้อง

Process number 1.5
Process name แก้ไข/ลบคำร้อง
Input data ข้อมูลแก้ไข/ลบ (จาก ผู้ดูแลระบบ)
Output data อัปเดต/ลบข้อมูล (ไปยัง D1 ข้อมูลคำร้องแจ้งซ่อม)
Data Store D1 ข้อมูลคำร้องแจ้งซ่อม
Process Description เป็นกระบวนการที่ผู้ดูแลระบบสามารถแก้ไขหรือลบคำร้องที่ผิดพลาดหรือไม่จำเป็นออกจากระบบ โดยอัปเดตหรือลบข้อมูลใน D1

กระบวนการที่ 1.5 เป็นขั้นตอนที่ผู้ดูแลระบบสามารถจัดการข้อมูลคำร้องแจ้งซ่อมที่มีข้อผิดพลาดหรือไม่จำเป็น โดยสามารถแก้ไขรายละเอียดคำร้องหรือลบคำร้องออกจากระบบ จากนั้นทำการอัปเดตหรือลบข้อมูลใน D1 ข้อมูลคำร้องแจ้งซ่อมตามคำสั่ง

กระบวนการที่ 1.6 แสดงตำแหน่งบนแผนที่

Process number 1.6
Process name แสดงตำแหน่งบนแผนที่
Input data ร้องขอดูแผนที่ (จาก ผู้ดูแลระบบ)
Output data ข้อมูลตำแหน่งบนแผนที่ (ไปยัง ผู้ดูแลระบบ)
Data Store D2 ข้อมูลอาคาร
Process Description เป็นกระบวนการแสดงตำแหน่งจุดแจ้งซ่อมบนแผนที่ โดยอ่านข้อมูลพิกัดอาคารจาก D2 และแสดงผลเป็นแผนที่แบบ Interactive

กระบวนการที่ 1.6 เป็นขั้นตอนที่ผู้ดูแลระบบสามารถดูตำแหน่งจุดแจ้งซ่อมบนแผนที่ โดยระบบจะอ่านข้อมูลพิกัดอาคารจาก D2 ข้อมูลอาคาร และแสดงผลเป็นแผนที่แบบ Interactive ผ่าน Leaflet ทำให้ผู้ดูแลระบบเห็นภาพรวมการกระจายตัวของปัญหาแจ้งซ่อมในแต่ละพื้นที่

กระบวนการที่ 2.0 การจัดการผู้ใช้งาน

กระบวนการที่ 2.0 การจัดการผู้ใช้งาน เป็นกระบวนการที่เกี่ยวข้องกับการจัดการข้อมูลผู้ใช้งานในระบบ ตั้งแต่การลงทะเบียน เข้าสู่ระบบ แก้ไข และลบข้อมูลผู้ใช้ โดยมี External Entity ที่เกี่ยวข้อง ได้แก่ ผู้ใช้งาน และผู้ดูแลระบบ มี Data Store ที่ใช้ คือ D4 ข้อมูลผู้ใช้ ประกอบด้วยกระบวนการย่อย 4 กระบวนการ ดังนี้

กระบวนการที่ 2.1 ลงทะเบียนผู้ใช้

Process number 2.1
Process name ลงทะเบียนผู้ใช้
Input data ข้อมูลการสมัครสมาชิก (จาก ผู้ใช้งาน)
Output data ผลลัพธ์การลงทะเบียน (ไปยัง ผู้ใช้งาน)
Data Store D4 ข้อมูลผู้ใช้
Process Description เป็นกระบวนการที่ผู้ใช้งานสามารถลงทะเบียนสมัครสมาชิกได้ โดยรับข้อมูลการสมัคร จากนั้นบันทึกข้อมูลผู้ใช้ลงใน D4

กระบวนการที่ 2.1 เป็นขั้นตอนที่ผู้ใช้งานใหม่สามารถลงทะเบียนเข้าสู่ระบบ โดยกรอกข้อมูลส่วนตัว เช่น ชื่อ-นามสกุล อีเมล รหัสผ่าน และข้อมูลอื่น ๆ ระบบจะทำการตรวจสอบความถูกต้องของข้อมูล เข้ารหัสรหัสผ่านด้วย bcrypt จากนั้นบันทึกข้อมูลผู้ใช้ลงใน D4 ข้อมูลผู้ใช้ และแจ้งผลลัพธ์การลงทะเบียนกลับไปยังผู้ใช้งาน

กระบวนการที่ 2.2 เข้าสู่ระบบ

Process number 2.2
Process name เข้าสู่ระบบ
Input data ชื่อผู้ใช้, รหัสผ่าน (จาก ผู้ใช้งาน)
Output data ผลลัพธ์การเข้าสู่ระบบ (ไปยัง ผู้ใช้งาน)
Data Store D4 ข้อมูลผู้ใช้
Process Description เป็นกระบวนการตรวจสอบสิทธิ์ โดยรับชื่อผู้ใช้และรหัสผ่าน ตรวจสอบกับข้อมูลใน D4 หากถูกต้องจะออก JWT Token อนุญาตให้ใช้งาน

กระบวนการที่ 2.2 เป็นขั้นตอนการตรวจสอบสิทธิ์การเข้าใช้งานระบบ เมื่อผู้ใช้งานกรอกชื่อผู้ใช้และรหัสผ่าน ระบบจะตรวจสอบข้อมูลกับ D4 ข้อมูลผู้ใช้ หากข้อมูลถูกต้องจะออก JSON Web Token (JWT) ให้ผู้ใช้งานสามารถเข้าถึงฟังก์ชันต่าง ๆ ตามบทบาทที่กำหนด หากไม่ถูกต้องจะแจ้งข้อผิดพลาดกลับไป

กระบวนการที่ 2.3 แก้ไขข้อมูลผู้ใช้

Process number 2.3
Process name แก้ไขข้อมูลผู้ใช้
Input data ข้อมูลแก้ไข (จาก ผู้ดูแลระบบ)
Output data ผลลัพธ์การแก้ไข (ไปยัง ผู้ดูแลระบบ)
Data Store D4 ข้อมูลผู้ใช้
Process Description เป็นกระบวนการที่ผู้ดูแลระบบสามารถแก้ไขข้อมูลผู้ใช้งาน เช่น ชื่อ อีเมล บทบาท โดยอัปเดตข้อมูลใน D4

กระบวนการที่ 2.3 เป็นขั้นตอนที่ผู้ดูแลระบบสามารถจัดการข้อมูลผู้ใช้งาน เช่น แก้ไขชื่อ อีเมล หมายเลขโทรศัพท์ หรือเปลี่ยนบทบาทของผู้ใช้ โดยอ่านข้อมูลเดิมจาก D4 ข้อมูลผู้ใช้ ทำการแก้ไขตามความต้องการ และอัปเดตข้อมูลใหม่กลับไปยัง D4 จากนั้นแจ้งผลลัพธ์การแก้ไขไปยังผู้ดูแลระบบ

กระบวนการที่ 2.4 ลบข้อมูลผู้ใช้

Process number 2.4
Process name ลบข้อมูลผู้ใช้
Input data คำสั่งลบผู้ใช้ (จาก ผู้ดูแลระบบ)
Output data ผลลัพธ์การลบ (ไปยัง ผู้ดูแลระบบ)
Data Store D4 ข้อมูลผู้ใช้
Process Description เป็นกระบวนการที่ผู้ดูแลระบบสามารถลบข้อมูลผู้ใช้งานที่ไม่ต้องการออกจากระบบ โดยลบข้อมูลออกจาก D4

กระบวนการที่ 2.4 เป็นขั้นตอนที่ผู้ดูแลระบบสามารถลบบัญชีผู้ใช้งานที่ไม่จำเป็นออกจากระบบ โดยรับคำสั่งลบจากผู้ดูแลระบบ ตรวจสอบว่าผู้ใช้ไม่มีงานค้างอยู่ จากนั้นดำเนินการลบข้อมูลออกจาก D4 ข้อมูลผู้ใช้ และแจ้งผลลัพธ์กลับไปยังผู้ดูแลระบบ

กระบวนการที่ 3.0 การจัดการอาคาร/สถานที่

กระบวนการที่ 3.0 การจัดการอาคาร/สถานที่ เป็นกระบวนการที่เกี่ยวข้องกับการจัดการข้อมูลอาคารและสถานที่ในระบบ ตั้งแต่การเพิ่ม แก้ไข ลบ ค้นหา และแสดงตำแหน่ง โดยมี External Entity ที่เกี่ยวข้อง ได้แก่ ผู้ดูแลระบบ และผู้ใช้งาน มี Data Store ที่ใช้ คือ D2 ข้อมูลอาคาร ประกอบด้วยกระบวนการย่อย 5 กระบวนการ ดังนี้

Process number 3.1
Process name เพิ่มข้อมูลอาคาร

Data Store D2 ข้อมูลอาคาร
Process Description เป็นกระบวนการที่ผู้ดูแลระบบเพิ่มข้อมูลอาคารใหม่ เช่น ชื่ออาคาร ที่อยู่ พิกัดตำแหน่ง โดยบันทึกลงใน D2

กระบวนการที่ 3.1 เป็นขั้นตอนที่ผู้ดูแลระบบสามารถเพิ่มข้อมูลอาคารหรือสถานที่ใหม่เข้าสู่ระบบ โดยกรอกข้อมูล เช่น ชื่ออาคาร รหัสอาคาร ที่อยู่ และพิกัดตำแหน่ง (ละติจูด/ลองจิจูด) สำหรับแสดงบนแผนที่ ระบบจะทำการบันทึกข้อมูลลง D2 ข้อมูลอาคาร และแจ้งผลลัพธ์การเพิ่มกลับไปยังผู้ดูแลระบบ

Process number 3.2

กระบวนการที่ 3.2 เป็นขั้นตอนที่ผู้ดูแลระบบสามารถแก้ไขข้อมูลอาคารที่มีอยู่แล้วในระบบ เช่น เปลี่ยนชื่ออาคาร แก้ไขพิกัดตำแหน่ง หรืออัปเดตที่อยู่ โดยระบบจะอ่านข้อมูลปัจจุบันจาก D2 ข้อมูลอาคาร แสดงให้ผู้ดูแลระบบแก้ไข จากนั้นอัปเดตข้อมูลใหม่กลับลงใน D2

กระบวนการที่ 3.3 เป็นขั้นตอนที่ผู้ดูแลระบบสามารถลบข้อมูลอาคารที่ไม่จำเป็นออกจากระบบ โดยรับคำสั่งลบจากผู้ดูแลระบบ ระบบจะตรวจสอบว่าอาคารนั้นไม่มีคำร้องแจ้งซ่อมที่ค้างอยู่ จากนั้นดำเนินการลบข้อมูลออกจาก D2 ข้อมูลอาคาร

กระบวนการที่ 4.0 การจัดการรายงาน

กระบวนการที่ 4.0 การจัดการรายงาน เป็นกระบวนการที่เกี่ยวข้องกับการสรุปข้อมูลและการแสดงผลรายงานต่าง ๆ เพื่อช่วยในการตัดสินใจ โดยมี External Entity ที่เกี่ยวข้อง ได้แก่ หัวหน้างาน และผู้ดูแลระบบ มี Data Store ที่ใช้ ได้แก่ D1 ข้อมูลคำร้องแจ้งซ่อม, D2 ข้อมูลอาคาร และ D4 ข้อมูลผู้ใช้ ประกอบด้วยกระบวนการย่อย 4 กระบวนการ ดังนี้

Process number 4.1
Process name สรุปสถิติการแจ้งซ่อม

Output data ข้อมูลสถิติสรุป (ไปยัง หัวหน้างาน)
Data Store D1 ข้อมูลคำร้องแจ้งซ่อม
Process Description เป็นกระบวนการสรุปสถิติการแจ้งซ่อม โดยอ่านข้อมูลจาก D1 ประมวลผลจำนวนคำร้องทั้งหมด คำร้องที่สำเร็จ และที่รอดำเนินการ

กระบวนการที่ 4.1 เป็นขั้นตอนการสรุปสถิติภาพรวมของการแจ้งซ่อมในระบบ เมื่อหัวหน้างานหรือผู้ดูแลระบบร้องขอ ระบบจะอ่านข้อมูลจาก D1 ข้อมูลคำร้องแจ้งซ่อม ประมวลผลจำนวนคำร้องทั้งหมด จำนวนที่ดำเนินการเสร็จสิ้น จำนวนที่อยู่ระหว่างดำเนินการ และจำนวนที่รอการมอบหมาย แสดงผลเป็นรายงานสรุปสถิติ

กระบวนการที่ 4.2 เป็นขั้นตอนการสรุปข้อมูลการแจ้งซ่อมจำแนกตามอาคาร โดยอ่านข้อมูลคำร้องจาก D1 ข้อมูลคำร้องแจ้งซ่อม และข้อมูลอาคารจาก D2 ข้อมูลอาคาร จากนั้นประมวลผลจำนวนคำร้องแจ้งซ่อมของแต่ละอาคาร แสดงผลเป็นรายงานให้หัวหน้างานเห็นว่าอาคารใดมีปัญหาแจ้งซ่อมมากที่สุด เพื่อใช้ในการวางแผนซ่อมบำรุง
